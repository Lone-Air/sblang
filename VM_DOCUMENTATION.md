/*
* SB Language - Bytecode Generator and Virtual Machine Documentation
*
* System Architecture Overview
* =============
*
* SB Language Compilation and Execution Process:
* 1. Lexical Analysis (Lexer): Converts source code into a sequence of tokens
* 2. Syntax Analysis (Parser): Converts a sequence of tokens into an Abstract Syntax Tree (AST)
* 3. Bytecode Generation (Bytecode Generator): Converts the AST into bytecode instructions
* 4. Virtual Machine (VM): Executes bytecode instructions
*
* =====================================
* Bytecode Generator
* =====================================
*
* Core Components:
* ---------
* 1. Instructions: Stores generated bytecode instructions
* 2. Constants: Stores constant values ​​in the program
* 3. Functions: Stores function definitions
* 4. Structures: Stores structure definitions
* 5. Globals: Records global variable names
*
* Main Functions:
* ---------
* - AST traversal and instruction generation
* - Jump address placement and backfilling
* - Symbol table management (functions, structures, global variables)
* - Bytecode serialization and deserialization
*
* Instruction Format:
* ---------
* Each instruction consists of an opcode (OpCode) and optional operands
* Operand types include: numbers, strings, and integers (jump addresses)
*
* ======================================
* Virtual Machine
* ​​===================================
*
* Core Components:
* ---------
* 1. Operand Stack (stack): Used for calculations and value transfer, size 1024
* 2. Call Stack (call_stack): Manages function calls, depth limit 256
* 3. Program Counter (pc): Points to the currently executed instruction
* 4. Variable Tables:
* - Global Variable Table (globals)
* - Local Variable Table (locals)
* 5. Function and Structure Definition Table
*
* Value Type System:
* -----------
* - VAL_NULL: Null value
* - VAL_NUMBER: Number (double)
* - VAL_STRING: String
* - VAL_BOOL: Boolean
* - VAL_FUNCTION: Function
* - VAL_NATIVE: Native Function
* - VAL_STRUCT: Structure Definition
* - VAL_STRUCT_INSTANCE: Structure Instance
* - VAL_LIST: List
*
* Instruction Execution:
* ---------
* The VM interprets and executes bytecode instructions, supporting:
* - Arithmetic operations: ADD, SUB, MUL, DIV, MOD, POW
* - Bitwise operations: AND, OR, XOR, NOT, LSHIFT, RSHIFT
* - Logical operations: AND, OR, NOT
* - Comparison operations: EQ, NEQ, LT, GT, LEQ, GEQ
* - Control flow: JUMP, JUMP_IF_FALSE, JUMP_IF_TRUE
* - Function Calls: CALL, RETURN
* - Variable Operations: LOAD_VAR, STORE_VAR, STORE_GLOBAL
* - Structure Operations: STRUCT_DEF, STRUCT_NEW, MEMBER_ACCESS, MEMBER_STORE
* - List Operations: LIST_NEW, LIST_ACCESS, LIST_STORE, LIST_PUSH
* - Module Loading: LOAD_MODULE
*
* Module System:
* ---------
* - Supports dynamic loading of .sb files
* - Modules execute in the same VM context
* - Inherits the main program's stack and variable environment
* - Complete compilation process: source code -> AST -> bytecode -> execution
*
* Native Function Interface:
* ---------
* - Supports registering C functions as native functions
* - Native function signature: Value (*)(VM*, Value*, int)
* - Built-in functions: print, input, tonumber, tostring
*
* Error handling:
* ---------
* The VM supports multiple error types:
* - RuntimeError
* - StackOverflow/Underflow
* - UndefinedVariable/Function
* - TypeError
* - DivisionByZero
* - IndexOutOfBounds
* - LoadError
* - MemoryError
*
* Memory management:
* ---------
* - All dynamically allocated memory has a corresponding release mechanism
* - String values ​​use a deep copy strategy
* - Automatically cleans up all resources when the VM is destroyed
* - Supports garbage collection framework (reserved interface)
*
* =======================================
* Usage examples
* =====================================
*
* 1. Compile source code to bytecode:
* ```c
* _sbToken* tokens = _sbLexer(source);
* Parser* parser = create_tkstate(tokens);
* ASTNode* ast = parse_program(parser);
* BytecodeGenerator* gen = create_bytecode_generator();
* generate_bytecode(gen, ast);
* ```
*
* 2. Execute bytecode:
* ```c
* VM* vm = create_vm();
* vm_register_native(vm, "print", native_print);
* vm_load_bytecode(vm, gen);
* vm_execute(vm);
* destroy_vm(vm);
* ```
*
* 3. Saving and loading bytecode:
* ```c
* save_bytecode(gen, "program.sbc");
* BytecodeGenerator* loaded = load_bytecode("program.sbc");
* ```
*
* ======================================
* Performance and limitations
* ======================================
*
* - Operand stack size: 1024 values, doubling as needed
* - Call stack depth: 256 levels, doubling as needed
* - Maximum number of global variables: 256, doubling as needed
* - Initial dynamic array capacity: 8, doubling as needed
* - Bytecode file format: binary, platform-dependent
